# Runnable Examples

The repository includes runnable TypeScript examples in `docs-site/examples/` (plus one AI Gateway
walkthrough in the repo-root `examples/` folder). They exercise the same public SDK APIs documented
in the guides and are run with `tsx` **from the repository root** — the root `tsconfig.json` maps
`@cdot65/prisma-airs-sdk` to `src/`, so a fresh clone needs no build step.

## Setup

Install dependencies and create an environment file:

```bash
npm install
cp .env.example .env
```

Fill in the credentials required by the workflow you want to run:

- Scan examples require `PANW_AI_SEC_API_KEY` or `PANW_AI_SEC_API_TOKEN`, plus
  `PANW_AI_SEC_PROFILE_NAME` (the name of an existing security profile in your tenant).
- Management and DLP examples require `PANW_MGMT_CLIENT_ID`, `PANW_MGMT_CLIENT_SECRET`, and
  `PANW_MGMT_TSG_ID`.
- Model Security, Red Team, and AI Gateway examples can use their service-specific
  `PANW_MODEL_SEC_*` / `PANW_RED_TEAM_*` / `PANW_AI_GW_*` credentials or fall back to `PANW_MGMT_*`.
- Validation scripts marked as mock-backed do not require live AIRS credentials or a `.env` file.

Run examples with:

```bash
npx tsx --env-file=.env docs-site/examples/<script>.ts
```

:::note[`--env-file` needs Node 20.6+ and an existing file]
`--env-file` is a Node.js flag (20.6+). The SDK itself supports Node 18, so on older runtimes
`export` the variables in your shell instead. Node also aborts with `.env: not found` if the file is
missing — which is why the mock-backed commands below omit the flag entirely.
:::

## AI Runtime Security Scan Examples

| Script             | What it demonstrates                                                              |
| ------------------ | --------------------------------------------------------------------------------- |
| `basic-scan.ts`    | Calls `init()`, creates `Content`, and runs `Scanner.syncScan()` with metadata.   |
| `async-scan.ts`    | Submits a 2-item batch with `Scanner.asyncScan()` (cap is 20) and polls the rows. |
| `query-results.ts` | Fetches scan results and threat reports by scan ID / report ID.                   |

```bash
npx tsx --env-file=.env docs-site/examples/basic-scan.ts
npx tsx --env-file=.env docs-site/examples/async-scan.ts
SCAN_IDS='uuid-1,uuid-2' REPORT_IDS='Ruuid-1' npx tsx --env-file=.env docs-site/examples/query-results.ts
```

## Management and DLP Examples

| Script                                | What it demonstrates                                                    |
| ------------------------------------- | ----------------------------------------------------------------------- |
| `mgmt-auth.ts`                        | Constructs `ManagementClient` and triggers OAuth on the first API call. |
| `mgmt-profiles.ts`                    | Creates, lists, updates, and deletes an AI security profile.            |
| `mgmt-topics.ts`                      | Creates, lists, updates, and deletes a custom topic.                    |
| `mgmt-dashboard.ts`                   | Reads runtime dashboard application and violation data.                 |
| `mgmt-dlp-data-filtering-profiles.ts` | Lists and reads DLP data filtering profiles (replace is commented out). |
| `mgmt-dlp-data-patterns.ts`           | Creates, reads, patches, and deletes a DLP data pattern.                |
| `mgmt-dlp-data-profiles.ts`           | Creates, reads, and merge-patches a DLP data profile (no DELETE exists). |
| `mgmt-dlp-dictionaries.ts`            | Creates (multipart), reads, replaces, and deletes a DLP dictionary.     |

```bash
npx tsx --env-file=.env docs-site/examples/mgmt-auth.ts
npx tsx --env-file=.env docs-site/examples/mgmt-profiles.ts
npx tsx --env-file=.env docs-site/examples/mgmt-topics.ts
npx tsx --env-file=.env docs-site/examples/mgmt-dashboard.ts
npx tsx --env-file=.env docs-site/examples/mgmt-dlp-data-filtering-profiles.ts
npx tsx --env-file=.env docs-site/examples/mgmt-dlp-data-patterns.ts
npx tsx --env-file=.env docs-site/examples/mgmt-dlp-data-profiles.ts
npx tsx --env-file=.env docs-site/examples/mgmt-dlp-dictionaries.ts
```

The `mgmt-profiles.ts`, `mgmt-topics.ts`, `mgmt-dlp-data-patterns.ts`, and `mgmt-dlp-dictionaries.ts`
scripts **create real resources** (named `sdk-example-*`) in your tenant and delete them again at
the end; `mgmt-dlp-data-profiles.ts` creates one it cannot delete. Run them against a non-production
TSG. With invalid or revoked OAuth credentials every one of them stops at the first call with
`AISEC_OAUTH_ERROR:Client authentication failed`.

## Model Security and Red Team Examples

| Script                       | What it demonstrates                                                       |
| ---------------------------- | -------------------------------------------------------------------------- |
| `model-security-scans.ts`    | Lists Model Security scans, evaluations, files, security groups, and rules. |
| `red-team-scans.ts`          | Lists Red Team scan jobs, categories, targets, quota, and statistics.       |
| `red-team-targets.ts`        | Reads Red Team targets, a target profile, and custom prompt sets.           |
| `red-team-network-broker.ts` | Lists, creates, updates, and inspects stats for network broker channels.    |

```bash
npx tsx --env-file=.env docs-site/examples/model-security-scans.ts
npx tsx --env-file=.env docs-site/examples/red-team-scans.ts
npx tsx --env-file=.env docs-site/examples/red-team-targets.ts
npx tsx --env-file=.env docs-site/examples/red-team-network-broker.ts
```

`red-team-network-broker.ts` creates a channel named `sdk-example-broker` and does not delete it
(the network broker API has no delete endpoint in the SDK).

## AI Gateway Example

A read-only walkthrough covering telemetry, the config plane, the admin plane, audit logs, and
error handling lives at [`examples/ai-gateway.ts`](https://github.com/cdot65/prisma-airs-sdk/blob/main/examples/ai-gateway.ts)
in the repository root:

```bash
npx tsx --env-file=.env examples/ai-gateway.ts
```

It needs the two SCM role grants described in the [AI Gateway guide](./ai-gateway-api.mdx#authorization);
with only one of them half of the calls return `403`.

## Mock-Backed Validation Scripts

These scripts spin up local mock servers or validate schemas directly, so they run without live
tenant credentials and without a `.env` file:

| Script                          | What it validates                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| `profiles-get-validation.ts`    | `profiles.get()` and `profiles.getByName()` behaviour, including pagination and not-found. |
| `profiles-crud-validation.ts`   | Management profile create, list, get, update, delete, and force-delete flow (33 checks).    |
| `oauth-lifecycle-validation.ts` | OAuth token caching, buffer-window refresh, expiry, 401/403 retry, callbacks, `clearToken`. |
| `red-team-mgmt-validation.ts`   | Red Team target/custom-attack Zod schemas plus `validate` param and CSV upload (37 checks). |

```bash
npx tsx docs-site/examples/profiles-get-validation.ts
npx tsx docs-site/examples/profiles-crud-validation.ts
npx tsx docs-site/examples/oauth-lifecycle-validation.ts
npx tsx docs-site/examples/red-team-mgmt-validation.ts
```
